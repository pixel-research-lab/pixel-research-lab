# 픽셀 연구실 · Research Lab

연구하며 떠오른 질문을 퀘스트로 남기고, 관찰한 결과를 기록해 픽셀 책상을 꾸미는 웹앱입니다. [연구실 열기](https://pixel-research-lab.github.io/pixel-research-lab/)

## 처음 시작하기

1. **연구 분야 설정**에 관심 분야를 입력합니다. 새 연구실은 새싹 화분 하나와 빈 퀘스트 보드, 복습 목록, 출퇴근 기록으로 시작합니다.
2. **퀘스트 등록**에서 자신의 질문을 적거나 **의뢰 뽑기**로 아이디어를 얻습니다. 의뢰는 수락할 때 퀘스트가 됩니다.
3. 여러 기기에서 이어가려면 같은 Google 계정으로 로그인합니다. 로그인 전 기록도 가져가려면 로그인 창에서 **이 브라우저의 게스트 기록도 내 계정으로 옮기기**를 선택합니다. 공용 브라우저 프로필에서는 게스트 기록을 함께 사용합니다.

## 플레이할 수 있는 기능

| 기능 | 사용 방법 |
| --- | --- |
| 연구 퀘스트 | 질문과 예측을 적고 도전 카드를 엽니다. 관찰한 근거와 결과를 남기면 스킬 경험과 장식을 얻습니다. 완료한 연구는 일지에서 다시 읽을 수 있습니다. |
| 복습 퀘스트 | 질문과 답을 등록하면 다음 날부터 **오늘의 퀘스트 → 복습 퀘스트** 추첨에 들어갑니다. 질문만 보고 떠올린 뒤 답을 확인합니다. **모르겠다**를 누르면 다음 날 다시 추첨 대상이 됩니다. 맞히면 3·7·14일 간격으로 복습하고, 4회 연속 정답이면 일지에 보관합니다. |
| 하루 복습 수 | **복습 관리 → 하루 6문제 · 설정**에서 문항 수를 바꿀 수 있습니다. 새 목록부터 적용되며, 기한이 된 문제가 더 적으면 전부 나옵니다. 틀린 문제를 우선하고, 나머지는 오래 기다릴수록 뽑힐 확률이 높아집니다. |
| 복습 XP | 연속 정답의 새 단계마다 10 XP를 받습니다. 해당 단계에서 먼저 모르겠다고 하면 1 XP를 미리 받고, 나중에 도달하면 차액만 받습니다. |
| 작업 책상 | 서랍의 아이템을 세 자리에 배치합니다. 현지 시각에 따라 해와 달이 움직이고 새벽과 노을, 밤의 스탠드가 나타납니다. 스피커는 온라인일 때 YouTube 홈을 새 탭으로 엽니다. |
| 출퇴근 | 연구 시작, 잠시 비움, 연구 재개, 퇴근을 기록합니다. 쉬는 시간은 제외하고 자정을 넘긴 시간은 날짜별로 나눕니다. 퇴근하면 저장되며 연구 일지에서 최근 7일을 볼 수 있습니다. |

## Token으로 연구실 꾸미기

새 연구실의 잔액은 **0 token**입니다. 연구 퀘스트를 끝내면 난이도에 따라 15·30·60 token, 복습 퀘스트에서 정답을 맞히면 6 token, 일정 퀘스트를 처음 완료하면 10 token을 받습니다. 기존 세이브도 완료 기록으로 잔액을 계산합니다. 예전 연구 퀘스트는 보통 난이도(30 token)로 계산합니다.

**연구실 꾸미기**에서 항목을 누르면 픽셀 방에 먼저 보여 줍니다. 구매를 확정하면 적용됩니다. 벽지·바닥·장비는 조합할 수 있고, 숲속·온실·옥탑·한강뷰 연구실 사이에서 이사할 수 있습니다. 이사해도 책상 장식, 퀘스트, 출퇴근 기록을 가져갑니다. 보유한 항목의 재적용과 이전 집으로 돌아가는 이사는 무료입니다.

**스킬 수첩 → 스킬 설정**에서 이름, 표시 여부, 새 스킬의 연습 방식을 정합니다. 연구 퀘스트에 연결한 스킬은 완료할 때 1 XP를 얻고, 연결한 복습 카드의 복습 XP도 그래프에 반영됩니다. 1~2개는 가로 막대, 3개 이상은 선택 수와 같은 꼭짓점의 방사형 그래프로 표시합니다. 숨긴 스킬을 다시 표시하면 기존 XP가 돌아옵니다.

체험용 단일 HTML을 만들려면 아래 명령을 실행한 후 브라우저로 결과 파일을 엽니다. 체험실에는 모든 유료 항목을 살 수 있는 **2,000 token**이 들어있고, 로그인 없이 별도 브라우저 저장소에 기록합니다.

```sh
python3 tools/studio-preview.py pixel-studio-demo.html
```

새 옵션은 `src/studio.js`의 카탈로그에 고유 ID, 표시 이름, 가격, 설명, 색을 넣고 `src/studio-art.js`에 픽셀 그림을 추가합니다. 구입 기록은 ID로 저장되므로 출시한 ID와 가격은 보존하세요.

## 저장과 동기화

각 기기에서 온라인으로 한 번 접속해 **오프라인 준비 완료**를 확인합니다. 로그인한 기록은 계정별 IndexedDB에 먼저 저장하고, 연결되면 Firebase에 동기화합니다. 다른 기기로 이동하기 전에는 **동기화 완료**를 확인하세요. Safari에서는 오프라인 작업 후 앱을 닫았다면 온라인에서 다시 열어 주세요.

오늘의 복습 목록과 문항 수 설정도 계정에 저장됩니다. 문제를 풀면 고정된 목록에서 남은 수만 줄어듭니다. 오프라인 기기들이 다른 목록을 먼저 만들었다면 동기화할 때 같은 날짜의 최초 추첨으로 합치며, 이미 남긴 답변 기록은 보존합니다.

구매 영수증과 스킬 정의는 항목별로, 꾸미기 선택은 벽지·바닥·장비·집별로 동기화합니다. 두 오프라인 기기에서 같은 잔액을 초과해 결제하면 구매 당시 예산 안에서 승인된 항목만 남습니다. 같은 항목을 두 번 사도 비용은 한 번만 반영됩니다.

서로 다른 퀘스트와 장식 자리는 독립적으로 합칩니다. 같은 퀘스트는 더 진행한 단계가 우선이고 같은 책상 자리는 최신 변경을 반영합니다. 같은 회차의 복습 보상도 한 번만 지급합니다. **세이브 관리**에서 JSON을 내보내거나 예전 데모 세이브를 불러올 수 있습니다.

조직 이전 전 주소에서 동기화한 연구실은 새 주소에 같은 Google 계정으로 로그인하면 이어집니다. 브라우저에만 있는 기록은 예전 주소에서 내보낸 JSON을 새 주소에서 가져오세요.

## 저장소 구조

| 경로 | 수정할 내용 |
| --- | --- |
| [src/](./src/) | 화면과 게임 로직. `app.js`는 조작과 화면, `data.js`는 스킬·의뢰·아이템, `art.js`는 방과 시간대별 조명을 그립니다. `reviews.js`, `attendance.js`, `transfer.js`는 복습·출퇴근·세이브를 담당합니다. |
| [assets/images/](./assets/images/) | 앱 아이콘과 마스코트 PNG. `items/`에는 책상 장식, `skills/`에는 스킬 아이콘이 있습니다. 같은 이름의 PNG를 교체하면 화면에 반영됩니다. |
| [assets/styles/](./assets/styles/) · [assets/fonts/](./assets/fonts/) | 화면 스타일, 픽셀 글꼴과 글꼴 라이선스. |
| [cloud/](./cloud/) · [firebase/](./firebase/) | Firebase 로그인, 계정별 동기화, 충돌 처리 소스와 Firestore 접근 규칙. |
| [dist/](./dist/) · [tools/](./tools/) | Firebase 브라우저·워커 번들, 오프라인 캐시 생성 도구와 서비스 워커 원본. |

루트의 `index.html`은 GitHub Pages 진입점입니다. `app.webmanifest`와 `sw.js`는 앱 설치 및 전체 프로젝트 경로의 오프라인 동작에 사용합니다.

## 함께 개발하기

저장소를 처음 받을 때 다음 명령을 실행합니다.

```sh
git clone https://github.com/pixel-research-lab/pixel-research-lab.git
cd pixel-research-lab
git switch -c feature/desk-items
python3 -m http.server 8000
```

브라우저에서 [로컬 연구실](http://localhost:8000/)을 엽니다. 미리 빌드한 번들이 포함되어 있어서 일반 화면과 게임 로직은 바로 테스트할 수 있습니다.

- **복습 로직 검증**은 루트에서 `node --test tests/daily-reviews.test.mjs`를 실행합니다.
- **화면·이미지 변경** 후 루트에서 `python3 tools/update-cache.py`를 실행해 오프라인 캐시를 갱신합니다. 새 스프라이트는 아이템 또는 스킬 ID를 파일 이름으로 사용합니다.
- **동기화 코드 변경** 시 Node.js 24.12 이상에서 `cd cloud`, `npm ci`, `npm run build`를 차례로 실행합니다. 루트로 돌아와 캐시를 갱신하고 생성된 `dist/`와 `sw.js`도 함께 커밋합니다.
- **변경 공유**는 기능 브랜치를 push한 뒤 `main`을 대상으로 Pull Request를 열면 됩니다. 병합된 웹 파일은 GitHub Pages에서 배포합니다.
- **Firestore 규칙 변경**은 Firebase 권한이 있는 계정으로 루트에서 `firebase deploy --only firestore:rules --project pixel-research-lab-2e2guk`를 실행합니다. 하루 복습 기능을 처음 배포할 때는 Pages에 병합하기 전에 이 명령으로 `reviewDraw`와 `reviewLimit`의 계정별 쓰기를 허용합니다. 꾸미기·스킬 그래프 배포 시에도 이 브랜치의 규칙을 먼저 배포해 구매·배치·스킬·일정 보상 기록의 쓰기를 허용합니다. 운영 로그인 도메인은 Firebase Authentication에서 관리합니다.

공개 배포본은 Google Analytics로 페이지 방문을 집계합니다. 연구 분야, 질문·답, 이메일 및 Firebase 사용자 ID는 앱의 방문 이벤트에 포함하지 않습니다.

## 캘린더와 모니터 포스트잇

책상 오른쪽 **오늘 할 일**에서 일정을 추가하거나 벽에 걸린 달력을 눌러 월간 화면을 엽니다. 오늘에 걸치는 일정은 퀘스트 보드와 모니터에도 나타납니다. 포스트잇을 눌러 완료하면 같은 일정의 세 화면이 함께 갱신됩니다. 완료 취소는 오른쪽 목록이나 달력에서 할 수 있습니다. ★로 표시한 예정 일정은 날짜와 함께 따로 보입니다.

**캘린더 연결**에서 연구실에 로그인하고 **Google 일정 읽기 연결**을 누른 뒤 표시할 캘린더 하나를 선택합니다. 선택한 달과 현재 달의 반복 일정을 회차별로 불러오고, 이미 받아 둔 일정은 오프라인에서도 열 수 있습니다. Google에 일정을 만들거나 수정하려면 쓰기 가능한 캘린더를 선택하고 **Google 일정 편집 연결**을 사용합니다. 완료와 별표는 연구실에만 기록합니다. Google에서 수정한 반복 회차는 해당 회차에만 반영합니다.

Google 전송 대기 중인 수정은 입력한 브라우저에 계정별로 보관합니다. 같은 계정으로 그 기기에서 앱을 열어 인터넷에 연결하고, 연결 시간이 끝났으면 편집 권한을 다시 연결하세요. 일정이 양쪽에서 달라졌으면 달력의 **대기 중인 수정**에서 어떤 버전을 사용할지 고릅니다. Google 접근 토큰은 메모리에만 둡니다.

- 테스트는 루트에서 `node --test tests/*.mjs`로 실행합니다.
- 운영 반영은 Firebase 프로젝트에 Google Calendar API가 활성화되어 있고 로그인 도메인이 허용되어 있는지 확인한 뒤, 이 브랜치의 Firestore 규칙을 배포하고 Pages에 병합합니다. 일정 본문, 별표, 완료 상태는 본인 계정에만 저장됩니다.
